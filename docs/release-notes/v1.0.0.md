# Dandelion v1.0.0

Dandelion is a self-hosted control room for a Linux development machine: one
Rust binary that serves a browser app for system health, processes, systemd
services, Docker, terminals, and the AI coding agents running on the machine.
It runs as a user service on the machine it controls and is reachable over
localhost and the Tailscale network.

This is the first release. Everything below is in the binary attached here.

## Highlights

**Dashboard.** Live CPU, memory, disk and load with sparklines, one-hour and
seven-day history charts from a local SQLite database, a host summary, and the
agents that need you — waiting or failed — at the top. The sidebar carries a
live host reading on every page.

**Agents.** The agents page lists managed agents from herdr-core (or classic
herdr as a fallback) and unmanaged Claude Code sessions. Selecting one opens a
chat surface: the rendered transcript above, the live terminal where the turn
happens, and the prompt at the bottom. A blocked question swaps in an answer
bar with Up/Down/Enter/Escape and a typed answer. Prompts, keys, answers,
interrupts and kills are all available; each mutating action writes one audit
row, and typed text never does.

**Transcript.** Claude Code's own transcript is streamed read-only and
rendered for reading: role accents, safe markdown with no raw HTML, collapsed
thinking and tool calls, nested subagents. Dandelion stores none of the
conversation content.

**Terminal.** A full terminal in the browser with tabs, over a real PTY:
`vim` and `htop` render, resizes propagate, and closing a tab ends the shell.

**Processes, services, containers.** Search and signal processes (TERM, KILL,
renice); list user and system units and read their journal tail, with system
units acting only through a sudoers allowlist; list, start, stop, restart and
read container logs.

**Live data.** One authenticated WebSocket carries every stream. The browser
keeps one connection per page, reconnects with backoff, and refetches on
reconnect so no event is lost to a gap.

**Phone.** The layout is usable at phone widths: the agent card fills the
screen, each pane can be enlarged over the chat, and focus changes do not
scroll the page.

## Security posture

- Single-owner login: a WebAuthn passkey and an argon2id password, set up from
  a one-time link printed by the server or `dandelion auth reset`.
- Sessions are server-side in SQLite and carried in an HttpOnly, Secure,
  SameSite=Lax cookie; logout and logout-all revoke them, and live sockets are
  closed on revocation or a failed 30-second recheck.
- Mutating API requests must carry a matching Origin (or
  `Sec-Fetch-Site: same-origin`); the WebSocket handshake is checked the same
  way.
- The server binds loopback only; TLS is not terminated by Dandelion.
  `tailscale serve` owns it.
- System unit actions go through a narrow sudoers allowlist generated from a
  TOML file; the app never runs arbitrary privileged commands.
- The UI is served with a Content-Security-Policy and `Referrer-Policy:
  no-referrer`.

## Install

Download the binary and its checksum, verify it, and install it as a user
service:

```sh
sha256sum -c SHA256SUMS --ignore-missing
install -m 0755 dandelion-v1.0.0-linux-x86_64 ~/.local/bin/dandelion
just install            # from a checkout: build, install units, enable, health check
just tailnet-serve      # expose loopback 7443 on the tailnet through Tailscale
```

`just install` needs the repository because it installs the systemd user units
from `packaging/`. Without a checkout, copy the three units from the release's
source tree and run `systemctl --user daemon-reload && systemctl --user enable
--now dandelion.service`.

The first start prints a single-use setup link in the journal
(`journalctl --user -u dandelion`).

## Upgrade and rollback

The data directory (SQLite database, migrations, audit log) is versioned by
embedded migrations that run on start. `just deploy` builds, writes a
pre-restart backup, installs the binary and units, and restarts. To roll back,
install the previous binary and restart; a database opened by a newer migration
is not downgraded, so restore its backup.

## Known limitations

- Web push notifications are not included: browser push requires a third-party
  push service, which this project does not use. Live state is in the app.
- Classic herdr is a fallback backend: it reports blocks without a reason, so
  the answer bar appears only for herdr-core agents.
- Passkey sign-in is covered by the end-to-end suite with a virtual
  authenticator; a real device passkey is exercised manually.
- Release artifacts carry a SHA-256 checksum, not a signature or provenance
  attestation.
