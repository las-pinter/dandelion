# Dandelion v1.2.0

Dandelion is a self-hosted control room for a Linux development machine: one
Rust binary that serves a browser app for system health, processes, systemd
services, Docker, terminals, documents, and the AI coding agents running on
the machine.

This release restyles the whole app and makes the theme follow the machine's
own light or dark setting.

## Highlights

**A flat, pressable interface.** Solid surfaces, hairline borders and one
shadow — the overlay — replace glass, gradients and glow. Every action is now
a control you can see: a border or a fill, a hover, a press that moves one
pixel, and a 2 px focus outline with an offset for the keyboard. Full screen,
the terminal pane toggles, Load earlier, and the row names in the agent,
process, service and container tables were bare text and are now buttons.
Status colours keep their meanings and their text labels.

**The theme follows the OS.** Until you choose, the app matches the system's
light or dark preference and keeps matching it while it stays open. The theme
button in the top bar saves an explicit choice, which then wins. The choice is
applied before the first paint, so there is no flash of the wrong theme, and
it applies to every screen, the sign-in pages included. An open terminal
repaints when the theme flips.

**Contrast is a test, not an intention.** `web/src/styles/tokens.test.ts`
reads the token stylesheet and fails if a text pair falls below WCAG AA in
either theme, or if an input's or button's border falls below the 3:1 non-text
contrast an affordance needs. The palette is a consequence of that test
passing, in both directions.

**Fewer ways to look wrong.** One button variant set, one radius scale, one
focus indicator, one border weight. `docs/design.md` is rewritten to describe
the system, and ADR-0009 records the decision and supersedes Mission Control.

## Housekeeping

- Every button, input and textarea now shares the same focus outline; the
  command palette's search field and the composer boxes are included.
- The Button primitive has a story with every variant, size and state, and the
  Storybook toolbar switches the whole preview between light and dark.
- Row bodies in the tables gain a hover fill, and a row's name control shows
  selection.
- The PWA manifest, the favicon and the pre-paint script follow the new
  palette, and a test keeps the hardcoded pre-paint values in step with
  `tokens.css`.

## Security posture

Unchanged: single-owner passkey and password login, server-side sessions in an
HttpOnly `__Host-` cookie with a 30-second recheck on live sockets, an Origin
check on every mutating request and on every WebSocket handshake, loopback-only
binding with TLS owned by `tailscale serve`, system-unit actions only through
the sudoers allowlist, and one audit row per mutating action. Typed prompts,
keys and answers are never stored; transcript content never leaves its file.
This release touches only styling, the theme bootstrap and tests; no auth,
input-validation or process-spawning code changed.

## Install

Download the binary and its checksum, verify it, and install it as a user
service:

```sh
sha256sum -c SHA256SUMS --ignore-missing
install -m 0755 dandelion-v1.2.0-linux-x86_64 ~/.local/bin/dandelion
just install            # from a checkout: build, install units, enable, health check
just tailnet-serve      # expose loopback 7443 on the tailnet through Tailscale
```

`just install` needs the repository because it installs the systemd user units
from `packaging/`. The first start prints a single-use setup link in the
journal (`journalctl --user -u dandelion`).

## Upgrade

There is no database migration and no configuration change in this release.
From a checkout on `main`:

```sh
git pull
just deploy             # rebuild, back up, replace the binary, restart
```

If you had never chosen a theme, the app now follows the OS instead of always
starting dark. Choose a theme with the button in the top bar to pin one.

## Known limitations

- The PWA manifest carries one splash colour, so an installed app on a dark OS
  still shows the light splash while it starts.
- The status colours are tuned for both themes, but a colour-blind reader
  relies on the text label beside each state, which is always present.
- Classic herdr remains a fallback backend and cannot report a blocked reason,
  so the answer bar appears only for herdr-core agents.
- Release artifacts carry a SHA-256 checksum, not a signature or provenance
  attestation.
