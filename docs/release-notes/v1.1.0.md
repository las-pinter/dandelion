# Dandelion v1.1.0

Dandelion is a self-hosted control room for a Linux development machine: one
Rust binary that serves a browser app for system health, processes, systemd
services, Docker, terminals, the AI coding agents running on the machine, and
now the documents those agents write.

This release adds the Documents page and makes the app load a page only when
it is visited.

## Highlights

**Documents.** A new page lists and displays documents that tools on this
machine write: HTML one-pagers and slide decks, and Markdown summaries. A tool
declares a collection by dropping a JSON manifest in
`~/.config/dandelion/plugins/<id>.json`; there is no Dandelion code change per
tool and no plugin code is ever loaded or run. Manifests name a root folder
under the home, include patterns with named captures, and the grouping order;
a manifest that breaks a rule appears as a warning row, missing at worst one
collection and never the page. The format is documented in
`docs/tech/documents-manifest.md`.

HTML documents are untrusted, so they are served with
`Content-Security-Policy: sandbox allow-scripts` — no `allow-same-origin`, no
network, no storage — and shown in an iframe with the matching `sandbox`
attribute. The document runs in an opaque origin that cannot call the API or
read the session cookie. Markdown is fetched as text and rendered in the app
with raw HTML disabled and only inline images drawn. Every requested path is
resolved against the manifest's root and include patterns: `..`, absolute
paths, unlisted files and symlinks answer 404, and a file above 8 MiB answers
413. Manifests, patterns and the file walk are bounded, so a hostile manifest
costs a warning row rather than memory or time.

**Faster first load.** Each page is now a small metadata module plus a screen
that loads on first visit. The entry chunk fell from 700 kB to 399 kB (217 to
126 kB gzip), and the agent transcript, the document viewer and the terminal
load their heavy dependencies only when their page opens. A first visit shows
one "Loading the page…" line; later visits are instant.

**Faster checks.** `just check` runs format, types, lint and the web tests in
seconds, for use after an edit batch; `just ci` remains the full gate.

## Security posture

Unchanged from v1.0.0 and still enforced: single-owner passkey and password
login, server-side sessions in an HttpOnly `__Host-` cookie with a 30-second
recheck on live sockets, an Origin check on every mutating request and on
every WebSocket handshake, loopback-only binding with TLS owned by
`tailscale serve`, system-unit actions only through the sudoers allowlist, and
one audit row per mutating action. Typed prompts, keys and answers are never
stored; transcript content never leaves its file. Documents add the
opaque-origin sandbox described above.

## Install

Download the binary and its checksum, verify it, and install it as a user
service:

```sh
sha256sum -c SHA256SUMS --ignore-missing
install -m 0755 dandelion-v1.1.0-linux-x86_64 ~/.local/bin/dandelion
just install            # from a checkout: build, install units, enable, health check
just tailnet-serve      # expose loopback 7443 on the tailnet through Tailscale
```

`just install` needs the repository because it installs the systemd user units
from `packaging/`. The first start prints a single-use setup link in the
journal (`journalctl --user -u dandelion`).

## Upgrade

There is no database migration in this release. From a checkout on `main`:

```sh
git pull
just deploy             # rebuild, back up, replace the binary, restart
```

To declare a document collection, write one manifest. For example, to show the
HTML and Markdown files a notes tree already holds:

```sh
mkdir -p ~/.config/dandelion/plugins
cat > ~/.config/dandelion/plugins/notes.json <<'JSON'
{
  "schema": 1,
  "id": "notes",
  "name": "Notes",
  "root": "~/notes",
  "include": ["{project}/**/*.{html,md}"],
  "group": ["project"]
}
JSON
```

The file stem must equal `id`. A relative `root` is refused; use `~` or an
absolute path under the home. The page shows why a manifest was skipped.

## Known limitations

- The document list refreshes when the page opens and on the Refresh button;
  there is no file watcher.
- Markdown renders fenced Mermaid blocks as code; diagrams are a later task.
- A Markdown image renders only when it is inline (`data:`); a remote image
  shows its alt text, so a document cannot make the app fetch a beacon.
- Classic herdr remains a fallback backend and cannot report a blocked reason,
  so the answer bar appears only for herdr-core agents.
- Release artifacts carry a SHA-256 checksum, not a signature or provenance
  attestation.
